# 0006. The pasted-block id is deterministic

Status: Accepted (2026-10-02)

## Context

Anthropic's guidance for Claude Opus is to wrap pasted material in tags whose opening and closing tag carry the same short
id generated by the application, so that text inside cannot close the block. A random id would make the same brief build a
different prompt each time, which breaks reproducible builds, prompt snapshot tests and the comparison between the AI
and the no-AI version.

## Decision

The Opus engine derives the id from the pasted text (a 32-bit FNV-1a hash, written `p` plus base 36), so the same text
always gets the same id: `<pasted_content id="…">` … `</pasted_content id="…">`. The id is not the security boundary.
The pasted text is escaped (`&` and `<`) so it cannot close the tag, and the prompt marks it as data, not instructions.
The other engines use `<document>` tags and carry no id.

## Consequences

- The local build is reproducible and testable; the backend recognises the block shape in the baseline.
- Anyone who can predict the pasted text can predict the id, which does not matter because the escape makes forging the
  closing tag impossible.
- The id is a stand-in for the documented "random" id, a deliberate deviation recorded in `docs/PROMPT-DOCS-REVIEW.md` (O3).

Revisit if the escaping is dropped or a vendor requires an unpredictable id.
